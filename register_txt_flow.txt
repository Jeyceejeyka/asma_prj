# Register (User Signup) Flow Documentation

This document describes the user registration (signup) flow as implemented in the Django backend. Follow these steps to replicate the same flow in another system.

---

## 1. API Endpoint
- **URL:** `/accounts/register/`
- **Method:** POST
- **Purpose:** Register a new user account.

## 2. Request Payload
Send a JSON object with the following fields:
- `username`: string (required, unique)
- `email`: string (required, unique, case-insensitive)
- `password`: string (required)
- `password2`: string (required, must match `password`)

Example:
```json
{
  "username": "newuser",
  "email": "user@example.com",
  "password": "StrongPassword123!",
  "password2": "StrongPassword123!"
}
```

## 3. Validation Logic
- **Email**: Must be unique (case-insensitive). Error if already exists.
- **Username**: Must be unique. Error if already exists.
- **Password**: Must meet password validation rules (Django's `validate_password`).
- **Password Match**: `password` and `password2` must match.

## 4. Registration Process
- Validate input using `RegisterSerializer`.
- If valid, create a new user:
  - Lowercase the email.
  - Set the password securely (`set_password`).
  - Save the user.
- Use a database transaction to ensure atomicity.

## 5. Response
- On success, returns:
  - `user`: Serialized user data.
  - `message`: Success message.
  - `refresh`: JWT refresh token.
  - `access`: JWT access token.
- **Status:** 201 Created

Example response:
```json
{
  "user": { ...user fields... },
  "message": "User registered successfully",
  "refresh": "<refresh_token>",
  "access": "<access_token>"
}
```

## 6. Error Handling
- Returns appropriate error messages for validation failures (e.g., duplicate email, password mismatch).

## 7. Implementation Files
- `apps/accounts/views.py`: Contains `RegisterView` (API endpoint logic).
- `apps/accounts/serializers.py`: Contains `RegisterSerializer` (validation and user creation logic).
- `apps/accounts/urls.py`: Maps the `/register/` endpoint to the view.

---

## To Re-implement This Flow
1. Create a serializer/class to validate and create users with the above rules.
2. Create an API endpoint (POST) that uses this serializer.
3. Ensure atomic database operations.
4. Return JWT tokens on success.
5. Map the endpoint in your URL/router config.
6. Follow the same validation and response structure for consistency.
